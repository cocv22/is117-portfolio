# IS117 Portfolio — Quantum Software Career Research

A small, public research site comparing two employer-hosted quantum software internship descriptions and explaining how a finding can inform a **proposed** portfolio feature and an explicit **planned** acceptance check.

**Project status:** Research and portfolio direction only. The quantum experiment described on the site is a proposal, not a completed simulation. No private career reflection or student-specific eligibility assessment is published here.

## Sources (checked November 11, 2026)

- [QuEra Computing — Internship: Scientific Software and Compilation](https://job-boards.greenhouse.io/queracomputinginc/jobs/5435902008)
- [Infleqtion — Summer 2027 Quantum Software Internship](https://apply.workable.com/coldquanta/j/EB77DE8198)

The page separates **employer-stated facts**, **assumptions and interpretations**, **alternatives**, a **proposed portfolio design**, and a **planned check**. Application details can change and should be verified on the original employer pages.

## Files

- `index.html` — Career research page with original source links, evidence, decisions, and planned verification.
- `styles.css` — Responsive presentation.
- `README.md` — Project purpose, boundaries, and publication guidance.

No build system or quantum simulation is required for this research assignment.

## Publish the documentation site

After reviewing and merging the career-research pull request, open **Settings → Pages** for this repository. Under **Build and deployment**, select **Deploy from a branch**, choose **main** and **/(root)**, then save.

The intended site address is [https://cocv22.github.io/is117-portfolio/](https://cocv22.github.io/is117-portfolio/). Verify that it actually opens after enabling Pages; this README does **not** claim it is live.

## Peer review and evidence trail

Ask the assigned classmate to pick one employer requirement and follow it from the linked source through the proposed portfolio feature to the planned acceptance check. Use GitHub issues for feedback and record whether each suggestion is accepted, deferred, investigated, or declined. If changes are made, link the issue to its PR/commit and any real verification; have the reviewer retry before closing an issue. A proposed test is not a performed test.

For a source-to-feature example, see the section **“One source. One checkable step.”** on `index.html`.
