03 / Evidence, inference, alternatives

Observe first.
Choose second.

What the descriptions actually support

QuEra emphasizes compiler infrastructure, prototype research, and reproducible experiments. Infleqtion emphasizes quantum algorithms, its software platform, and professional testing and collaboration. Both value programming and clear communication.

What is still an assumption

A small quantum-circuit experiment may be useful portfolio evidence, but neither employer promises that such a project would satisfy its hiring requirements. The proposed reader's preferences have not been independently interviewed or tested.

Alternatives considered

A compiler-internals study would closely reflect QuEra's work but could require specialized background before producing a clear example. A small quantum algorithm simulation could be easier to explain and verify while remaining relevant to both descriptions.

Proposed direction: Begin with a documented Python/Qiskit experiment and consider deeper compilation work after establishing repeatable results. This decision is a learning plan, not evidence that the project has already been implemented.

04 / Finding to proposed feature and check

One source.
One checkable step.

Source detail: QuEra lists prototypes, experiments, benchmarks, and reproducible examples; Infleqtion emphasizes tests, documentation, and quantum programming frameworks.

Inference: A reviewer could more easily assess a programming claim if a project shows the code, an expected theoretical result, an observed simulated result, and how the two were compared.

User story (proposal): As a technical portfolio reviewer, I want to see a reproducible quantum circuit experiment with its expected and observed results, so I can understand what the project actually demonstrates.

Proposed portfolio feature: A public project README that links to Python/Qiskit source code, one simple circuit, the mathematics behind an expected outcome, and a recorded check.

Planned acceptance check, not an observed result: After the project exists, a reviewer should be able to follow its setup instructions, run the small circuit, and compare its output with the documented theoretical expectation. Record the actual result only after a real attempt.

Potential revision trigger: If a reviewer cannot find the expected result or reproduce the example, revise the README or test instructions and ask them to retry.
